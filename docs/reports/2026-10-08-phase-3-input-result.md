# 3단계 교사 입력 개선 — 1차 결과

상태: 명단 점수·빠른 관찰·마감 구현 및 코드 검사 통과. 실제 UI·인수 대기. 단계 전체 완료 아님.

## 체험 경로

1. 교사 → 수업 기록. 학생별 정답수에 23, 24, 30, 0을 입력하고 다른 학생은 빈칸으로 둠.
2. ‘입력한 점수 저장’. 입력한 학생만 기록되며 FAIL 학생만 나머지 지정 창에 이어짐.
3. 지정 창을 닫았으면 ‘최근 FAIL 학생 나머지 지정’으로 다시 연결. 같은 본시험을 이미 지정했다면 중복 생성을 차단함.
4. 학생 선택 → 관찰 기록 → 빠른 관찰 태그. 추가 메모 없이도 태그의 사실을 저장 가능. 직접 작성도 유지.
5. 점수 미입력이거나 모두 저장했을 때 ‘특이사항 없음 · 수업 마감’. 데모 날짜·반·기록자별 마감 기록 저장. 학생 관찰을 자동 생성하지 않음.

## 검증

- 서로 다른 학생의 23/24/30/0점, 빈칸 제외, FAIL 학생만 선택.
- 31점 포함 시 아무 점수도 부분 저장하지 않음.
- 저장 실패 시 데이터 복구·점수 유지, 재시도 후 중복 없음.
- 반 이동 후 입력 유지, 조교의 명단 점수 저장 차단.
- 명단형 본시험 ID 연결 과제 중복 생성 차단.
- 빠른 태그 2명 기록, 미저장 점수 마감 차단, 마감 실패·재시도·같은 날짜 중복 마감 차단.
- 기존 모델·화면 템플릿·역할 체험·저장 복구 검사 통과.

## 남은 작업과 제한

점수 초안은 메모리에만 보존되어 새로고침 시 소멸함. 화면에 안내하고 나가기 경고를 요청하지만 실제 브라우저 경고 표시는 미검증. 최근 FAIL 연결도 현재 실행 세션에 한정됨.

기존 팝업 시험 및 수동 지정 전반의 시험 식별·중복 처리는 아직 통합하지 않음. 수업 마감은 데모 날짜/반/기록자 단위이며 같은 날 여러 차시 관리가 아님.

실제 브라우저 UI·모바일·사용 시간은 접근 제한으로 미검증. 계약의 완료 기준에 따라 완료 커밋 보류. GitHub push 없음. 이전 미커밋 변경 보존.

## 추가 승인 범위 결과 · 선택 복습 연결

사용자 ‘추가 12회로 진행’ 승인 범위에서 구현. 새 과제의 추가 과제는 선택 복습 기본값이며 교사가 필수로 변경 가능. 기존 필수성 필드 없는 과제는 계속 필수로 처리하고 저장 데이터를 초기화하지 않음.

- 기본 과제 통과 시 선택 복습이 남아도 필수 과제 완료로 집계. 완료 목록에서 선택 복습을 별도로 완료 처리 가능.
- 완료 과제의 귀가·중복 결과 처리를 막고, 선택 잔여만으로 미완료 안내를 만들지 않음.
- 완료된 과제의 검토/승인 대기 안내는 취소. 이미 모의 발송했다면 발송 시각을 유지하고 후속 확인 필요로 표시.
- 필수 추가 과제가 남으면 학습중 유지. 기존 안내 대상이 기본 과제에서 추가 과제로 바뀌면 이전 승인·발송 이력을 보관하고 새 내용은 다시 검토.
- 모델·템플릿·역할 체험·명단 입력·저장 복구 및 test-task-policy.cjs 통과. 필수 잔여 변경 후 이전 승인 재사용 회귀 사례는 실패를 확인하고 수정 후 통과.

체험: 교사가 새 과제를 선택 복습으로 지정 → 조교가 해당 과제의 기본 과제 통과 처리(기본 단어 시험은 30개 중 24개 이상) → 완료 목록에서 선택 복습 잔여 표시 확인 → 선택 복습 완료. 필수 추가 과제로 지정한 새 과제는 기본 통과 후에도 학습중으로 유지됨.

이번 연결은 4단계 전체 완료가 아님. 잔여 범위 입력·다음 확인일·일반 정정 이력·리포트 버전 보존은 미구현. 실제 브라우저 검증 및 완료 커밋은 계속 보류하며 GitHub push 없음.

## 후속 결과 · 본시험 연결 통합

사용자 ‘작업계약 나머지 진행 + 프론트엔드를 업그레이드 할 방법 고민’에 따라 3단계의 남은 시험 연결을 먼저 구현함. 이전 기록의 팝업·수동 지정 연결 미구현 항목을 아래 결과로 갱신한다.

- 팝업 FAIL 저장 후 학생별 시험 ID를 지정 화면에 전달. 명단형·팝업형 모두 같은 근거 시험 선택 UI 사용.
- 수동 지정에서는 학생별 FAIL 시험을 명시적으로 선택하거나 시험 연결 없이 별도로 지정. 새로고침 후에도 저장된 시험 선택 가능.
- 중복 판정은 학생·근거 시험·사유·기본 과제·추가 과제·필수 여부가 같은 경우. 공백 차이는 정규화. 같은 시험의 다른 과제, 다른 시험의 같은 과제는 허용.
- 과거 연결 없는 과제는 임의 추정·소급 연결하지 않음. 따라서 과거 미연결 과제와의 자동 중복 탐지는 보장하지 않음.
- test-assignment-links.cjs: 팝업 연결 누락 실패를 먼저 확인한 후 수정. 연결·중복·다른 과제·다른 시험·다중 학생·타 학생 연결 차단·명시적 미연결·저장 실패/재시도·재조회·PASS 사례 통과.
- 기존 모델·템플릿·역할 체험·명단·선택 복습 정책·저장 검사 통과. 실제 UI 확인은 여전히 대기. 전체 단계 완료 커밋 없음.

남은 계약 범위: 관찰 입력의 이탈/미저장 보호 확인, 실제 UI와 사용자 인수, 조교 잔여 범위/교사 확인일, 정정 이력, 승인 리포트 버전 보존. 프론트엔드는 별도 개선 방향 문서만 작성하며 대규모 변경하지 않음.
