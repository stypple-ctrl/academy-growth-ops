## 목적과 범위

추가 과제, 이월 책임, 기록 정정, 승인 리포트 변경의 기준을 문서로 확정한다. 가상 학생 사례에서 완료 상태·다음 담당자·알림 여부를 대조한다. 이번 단계는 운영 기준 확정이며 앱 동작이나 저장 데이터 구조를 변경하지 않는다.

2026-10-08 사용자의 ‘작업계약서에 따라 다음단계 순차진행’은 계약 대조·다음 단계 준비 및 합의된 범위의 순차 실행 요청으로 기록한다. 이후 사용자의 ‘2단계운영기준으로 진행’을 제시한 권장 운영 기준 채택으로 기록한다. 1단계 인수 사실로 대신 기록하지 않는다.

## 확정한 운영 기준

| 항목 | 확정 기준 | 현재와 달라지는 점 / 영향 |
|---|---|---|
| 추가 과제 | 기본은 선택 복습, 교사가 지정할 때 필수로 전환 가능 | 현재는 추가 과제까지 해야 최종 완료. 이후 교사 지정·조교 처리·집계를 함께 변경해야 함 |
| 완료 표시 | 필수 과제가 전부 끝나면 완료. 선택 복습 잔여는 별도 표시하고 미완료 인원·필수 과제 완료율에서 제외 | 선택 복습을 하지 않았다는 이유만으로 미완료 귀가 알림을 만들지 않음 |
| 이월 책임 | 조교가 완료·남은 범위를 기록, 담당교사가 다음 확인일 지정. 날짜 지정 전에는 ‘교사 확인 필요’로 유지 | 필수 과제 잔여만 이월 관리. 다음 확인일 자동 추정 금지 |
| 정정 | 원본 보존 + 정정 내용·사유·수정자·시각 기록. 집계는 유효한 최신 값 기준 | 학생 타임라인에서 무엇이 바뀌었는지 추적 가능해야 함 |
| 승인 리포트 | 승인 당시 본문·근거를 보존. 근거 정정 시 ‘수정 필요’, 새 버전 작성·재검토 | 승인본을 조용히 덮어쓰지 않음. 실제 발송·AI는 포함하지 않음 |

알림 기준: 필수 과제를 남기고 귀가하면 학부모 안내 ‘검토 필요’ 초안 생성. 교사 검토 후 모의 발송만 가능. 선택 복습만 남으면 미완료 귀가 알림을 생성하지 않음. 정정으로 미완료 사유가 해소되면 미발송 안내는 취소 대상으로 표시하며, 이미 모의 발송한 기록은 보존하고 정정 안내 필요 여부를 교사가 확인한다.

## 실행 순서와 완료 기준

1. 1단계 남은 실제 UI 확인·인수 상태 확인. 사용자가 직접 확인한 범위는 사용자 확인으로 기록하며 에이전트 브라우저 검증으로 표현하지 않음.
2. 위 운영 기준에 대한 사용자 선택 기록. 수정 요구가 있으면 해당 기준과 관련 사례만 조정.
3. 다섯 사례에서 상태·담당자·잔여 범위·알림 처리에 모순이 없는지 같은 에이전트가 후속 검토.
4. 정책 확정본과 README 상태 갱신. 완료 조건을 충족한 문서만 명시적으로 스테이징해 로컬 커밋. 기존 미커밋 앱 변경을 섞지 않음.
5. 확정 기준에 따라 3단계 교사 입력 작업의 구체적 범위·검증 계획 작성. 미정 운영 기준을 임의로 구현하지 않음.

완료 기준: 사용자 결정이 문서에 명시되고 사례 인수표가 그 결정과 일치함. 결정 대기 상태에서는 2단계 완료나 후속 정책 구현 완료로 보고하지 않음.
