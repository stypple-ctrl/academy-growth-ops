# 3단계 교사 입력 개선 — 실행 범위 준비

2026-10-08 / 2단계 확정 기준 기반 / 구현 미착수.

## 착수 전 확인

1단계 실제 UI·사용자 인수는 아직 답변 대기. 현재 정책 문서 확정과 구분한다. 선행 확인 및 이후 구현 범위 대조 후 순차 진행한다. 새 운영정책을 기존 데이터에 소급 적용하거나 초기화하지 않는다.

## 구현 순서

1. 명단에서 학생별 정답수를 입력한다. 빈칸은 미입력으로 건너뛰며 0과 구분한다. 정수·범위 검증을 전체 입력에 수행한 뒤 한 번에 저장한다. 오류·저장 실패 시 입력을 유지한다.
2. 관찰 유형·영역·빠른 태그로 기록한다. 태그 또는 자유메모 중 하나는 있어야 기록하며 미선택을 관찰 사실로 저장하지 않는다.
3. 본시험 저장 후 FAIL 학생 선택을 유지해 나머지 지정으로 이어간다. 본시험 ID와 과제의 연결로 동일 시험의 중복 지정을 알리고, 다른 시험·다른 과제는 허용한다.
4. 수업 마감 시 특이사항 없음도 명시적으로 기록한다. 미저장 점수·관찰이 있으면 먼저 처리하도록 안내한다.
5. 기본 과제·추가 과제의 필수 여부 입력을 설계한다. 새 과제의 선택형 기본값을 활성화할 때는 조교 완료·인원 집계·알림까지 같은 기준으로 처리돼야 한다. 입력만 선택형으로 바꾸고 조교는 필수로 처리하는 불일치를 배포하지 않는다. 이 연결 작업은 4단계와의 의존 항목으로 별도 명시하고 최소 범위를 확정한다.

## 검증 사례

- 서로 다른 학생의 23/24/30점과 미입력, 명시적 0점.
- 12명 중 2명만 관찰 입력, 잘못된 점수 포함 시 부분 저장 없음.
- 저장 실패·재시도 후 점수와 관찰 중복 없음.
- 같은 본시험 중복 지정 알림, 서로 다른 과제 정상 지정.
- 특이사항 없음 마감 기록, 미저장 입력 보호.
- 과거 과제의 필수성·기록 보존. 선택형 활성화 시 기본 통과 후 완료·선택 잔여·알림 일치.
- 실제 UI 체험 후에만 처리 시간과 인수 완료 판단.

## 범위 제한

DB·로그인·실제 AI·발송·추가 디자인 변경 없음. 1명·도구 호출 단계당 12회 기본. 작업을 작은 구현 묶음으로 나누고 초과 전 보고한다. 이 문서는 다음 단계 구체화 산출물이며 구현 완료 보고가 아니다.
