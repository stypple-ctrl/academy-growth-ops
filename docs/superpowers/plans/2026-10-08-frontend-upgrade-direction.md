# 프론트엔드 업그레이드 방향 · 2026-10-08

상태: 단일 에이전트의 코드·사용자 요구 기반 검토안. 실제 화면을 관찰한 감사 결과가 아니며 디자인 구현 승인을 대신하지 않음.

## 판단

현재 macOS 테마와 학생 갤러리를 유지하고 역할별 정보 우선순위와 입력 동선을 개선한다. 프레임워크 교체는 이번 문제의 선행 조건이 아니다. vanilla JS/CSS 위에서 작은 화면 단위로 변경하고 저장·집계 회귀 검사를 유지한다.

Impeccable의 Operate 원칙(업무 수행·스캔성·일관성·절제된 동작)을 참고했다. context 실행기는 Permission denied로 실행되지 않아 기존 코드와 계획을 읽었다. PRODUCT.md/DESIGN.md는 현재 없으며 임의로 제품 사실을 만들지 않았다. 정식 critique는 2개 하위 에이전트를 요구하므로 사용자 단일 에이전트 지침에 따라 실행하지 않았다. 감지기·시각 감사 점수는 없음.

## 화면별 방향

| 대상 | 코드와 요구에서 확인한 현황 | 개선 제안 | 체험 완료 기준 |
|---|---|---|---|
| 원장 | 신입 적응·재원 관심·교사 관리 표시가 이미 있음 | 첫 화면을 긴급 조치→신입 적응→반/교사 추이로 정렬. 각 알림에 근거·담당·다음 확인을 한 묶음으로 표시 | 사용자가 첫 화면에서 먼저 챙길 학생과 다음 행동을 설명할 수 있음 |
| 교사 | 명단 점수·빠른 관찰·팝업 시험이 병존 | 명단 입력을 주 동선으로 강조. Enter/방향키 이동, 학생 행의 저장/오류 상태, 한 학생 상세 패널 검토 | 마우스 왕복 없이 점수 입력·오류 수정·FAIL 지정 완료. 처리 시간은 실제 측정 |
| 조교 | 상태별 갤러리·지시서 확대·완료 접기 구현 | 출근 후 변경 사항과 확인대기를 우선 배치. 카드에는 학생·필수 과제·완료 조건·다음 행동을 고정 위치에 표시 | 지시서를 찾아 헤매지 않고 남은 범위를 기록하고 교사에게 인계 |
| 공통 | 기본 스타일+갤러리+macOS 테마가 순서대로 덮어씀 | 기능 수정 후 필요한 컴포넌트부터 색/간격/상태 토큰 정리. 전체 CSS 재작성은 피함 | 버튼·입력·오류·포커스 상태가 화면마다 일관적 |

## 적용 순서

1. 계약 잔여 기능: 관찰 미저장 보호 → 조교 잔여 기록·교사 확인일 → 정정 → 승인본 보존. 상태 정의가 정해진 뒤 화면에 반영.
2. 가벼운 공통 개선: 한국어 문구·숫자 정렬·버튼 우선순위·포커스·오류 위치. 기존 상태 색의 의미 유지.
3. 교사 명단 입력과 조교 카드 중 한 화면씩 실제 체험 확인. 관찰 결과에 따라 다음 화면 변경.
4. 원장 화면은 실제 근거가 있는 조치·추이 중심으로 정리. 기록 건수만으로 교사의 태도나 실력을 평가하지 않음.
5. 마지막에 버튼/모달 전환만 Emil 지침으로 다듬기. 반복 입력에는 장식 애니메이션을 추가하지 않음.

## 검증·제한

역할별 핵심 흐름, 저장 실패/재시도, 키보드 이동, 좁은 화면의 입력/버튼 접근성을 확인한다. 실제 브라우저 접근 제한을 우회하지 않고 해소 전에는 화면 검증 완료라 하지 않는다. UI 확인은 단계당 스크린샷 2회 한도. 추가 에이전트·이미지 생성·외부 모델·자동 반복 실행 없음. 이번 결과에는 제안 UI의 구현이나 실제 성능 측정이 포함되지 않는다.
