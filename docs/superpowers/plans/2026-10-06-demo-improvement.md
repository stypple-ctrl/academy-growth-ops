**Tech Stack:** HTML, CSS, Vanilla JavaScript, Node.js 내장 assert/vm 테스트, Python 정적 서버.

**Spec:** `/Users/andy/Downloads/academy_growth_ops_PRD_v1_1.docx` 및 이 대화의 테스트 버전 범위, 디자인 참고, 사람·흐름·데이터·권한·출력·복구 진단.

## Global Constraints

- 계획 수립 요청이며 현재 앱 코드는 수정하지 않는다.
- 실제 학생 데이터, DB, AI 호출, 실제 문자 발송을 이번 체험판 개선에 추가하지 않는다.
- 기본은 현재 에이전트 1명. 단계당 실제 도구 호출 12회 이내, 초과 전 사용자 승인. UI 스크린샷 단계당 최대 2회.
- 같은 원인의 실패는 최초 시도 후 근거 있는 재시도 1회까지.
- 통과한 검증은 변경이나 새로운 위험이 없으면 반복하지 않는다.
- 저장 데이터 자동 초기화 금지. 초기화가 필요하면 별도 확인한다.
- 기존 민트·연두색 및 입체형 컨트롤 방향을 유지한다. 광범위 리팩터링과 디자인 재작업은 포함하지 않는다.
- 브라우저 접근은 저장된 권한으로 차단되어 있다. 우회하지 않는다. 실제 UI 검증은 사용자가 해당 접근을 허용한 뒤 실시하거나 사용자가 체험하고 피드백한다. 코드 검증을 실제 클릭 검증으로 표현하지 않는다.
- 모든 단계의 자동 진행을 가정하지 않는다. 승인받은 작업 범위만 구현한다.

## 순서와 의존관계

0. 현재 상태 보존 → 1. 좁은 신뢰성 오류 수정 → 2. 나머지 운영 기준 결정 → 3. 교사 입력 개선 → 4. 조교·인계·정정 흐름 → 5. 원장 화면 및 리포트 → 6. 실제 운영 기반.

- 0단계는 1단계 착수에 포함한다. 별도 대규모 작업으로 만들지 않는다.
- 2단계는 코드를 쓰기 전 짧은 운영정책 결정이다. 다른 화면의 완료 기준과 입력값이 달라지므로 앞에 둔다.
- 3단계에서 만들어진 시험·지정 데이터를 4단계에서 처리하고 5단계에서 출력한다.
- 6단계는 별도 계획이다. 실제 개인정보 투입 전 필수이며 현재 개선 작업에 포함하지 않는다.

### Task 1: 조교 미확인 기본값 수정

**Files:** Modify `app.js`, `model.js`; Test `test-model.cjs`, `test-render.cjs`.
**Interfaces:** 기존 `Growth.result(db, task, action, actor, correct)` 및 `task.help`, `task.progress`를 유지한다. 미선택은 속성 누락으로 보존하고 표시만 '미확인'으로 한다.

- [ ] 미선택 상태에서 결과 저장 시 '혼자 수행'·'원활'이 생기지 않는 회귀 검사를 추가한다.

```js
const db = G.seed();
const task = db.tasks[0];
G.result(db, task, '시작', '조교');
G.result(db, task, '결과', '조교', 24);
const fact = db.events.filter(e => e.student === task.student && e.type === '수행 사실').at(-1);
assert(!fact || (!fact.text.includes('혼자 수행') && !fact.text.includes('원활')));
```

- [ ] 회귀 검사 실패를 확인한 뒤 선택 옵션 첫 항목을 값 없는 '미확인'으로 변경한다. 모델의 미확인 대체 문구도 동일하게 바꾼다. 미선택을 억지로 관찰 기록으로 만들지 않고, 실제 선택된 항목만 사실 기록에 넣는다.
- [ ] 실제 '혼자 수행'을 선택했을 때는 해당 사실이 기록되는지 확인한다. 이전에 저장된 값은 근거 없이 변경하지 않는다.

### Task 3: 저장 실패를 성공으로 안내하지 않기

**Files:** Modify `app.js`; Create `test-storage.cjs`; Update `README.md`.
**Interfaces:** `save()`는 boolean을 반환한다. 실패 시 현재 입력·선택을 보존하고 '이 브라우저에 저장하지 못했습니다'를 안내한다. 성공에 종속된 닫기·선택 해제·완료 안내는 반환값이 true인 경우에만 실행한다.

```js
function save() {
  try {
    localStorage.setItem(KEY, JSON.stringify(db));
    return true;
  } catch {
    toast('저장하지 못했습니다. 입력 내용을 유지했습니다.');
    return false;
  }
}
// 저장 액션의 성공 처리 전: if (!save()) return;
```

- [ ] 기존 VM 테스트 환경에 `setItem(){ throw new Error('QuotaExceededError'); }` 저장소를 주입한다.
- [ ] 실패 시 성공 메시지·모달 닫기·선택 초기화가 발생하지 않는 검사를 먼저 추가한다.
- [ ] 데이터 변경 후 실패한 경우 저장 전 스냅샷으로 인메모리 변경을 되돌리거나 미저장 변경을 명시적으로 관리한다. 첫 단계에서는 액션별 스냅샷 복구를 사용해 재시도 중 사건 중복이 생기지 않게 한다.
- [ ] 실패 후 저장소를 정상으로 바꾸고 같은 입력을 다시 저장했을 때 기록이 정확히 한 번 생성되는지 확인한다.
- [ ] 정상 저장 시 새 앱 인스턴스에서 기록을 다시 읽을 수 있는지 검증한다.

## 3단계 — 교사 입력 흐름 개선 (별도 실행 계획)

- 학생별 정답수를 명단 표에서 입력한다. 빈칸은 0점이 아닌 미입력이다.
- 관찰은 유형·영역·자주 쓰는 태그로 입력하고 자유메모는 선택으로 둔다.
- 시험 저장과 나머지 지정은 선택한 학생을 이어서 처리할 수 있게 한다.
- 수업 마감 시 특이사항 없음도 명시적으로 저장한다.
- 실제 본시험 ID와 나머지 지정의 연결을 만들고 같은 과제 중복은 알려준다. 서로 다른 정상 과제는 허용한다.
- 학생 선택 오류·점수 범위 초과·일괄 저장 중 실패에 대해 입력을 보존한다.

검증: 12명 중 2명 관찰 기록, 학생별 23/24/30 및 빈 점수, 한 학생의 두 정상 과제, 중복 클릭, 저장 실패 후 재시도. 60초/2분 목표는 실제 사용 시간을 측정했을 때만 달성으로 보고한다.

## 4단계 — 조교 처리 및 교사 인계 (별도 실행 계획)

- 2단계 정책에 맞춰 기본·추가 과제 상태와 귀가 상태를 분리한다.
- 완료 범위·남은 범위·귀가시간·다음 확인일을 기록한다.
- 조교 인수, 교사 결과 확인을 구분한다. 모든 일반 관찰에 승인 절차를 추가하지 않는다.
- 완료/귀가 정정 시 변경 이력과 알림 상태를 함께 갱신한다. 단순 데이터 삭제로 되돌리지 않는다.
- 학생별 귀가시간 기준 정렬, 사용 중 경과시간 갱신, 처리 실수 복구를 제공한다.

검증: 기본 통과+선택 복습 잔여, 필수 추가 과제 미완료, 부분완료 이월, 귀가 정정, 인계 확인, 알림 승인 후 정정. 조교 1명이 10명 처리를 실제 UI로 체험하고 15초 목표는 측정한다.

## 5단계 — 원장과 학부모 출력 (별도 실행 계획)

- 김민수 등 가상 학생 3명에 개선·장기 미해결·안정적 강점의 다른 학습 사건과 근거를 구성한다.
- 원장에게 확인 기한 경과, 미인수 업무, 다음 조치와 담당자를 우선 표시한다. 근거 없는 위험 점수는 만들지 않는다.
- 기록 건수 그래프보다 본시험 통과율, 미완료 경과일 등 의미 있는 지표를 사용한다. 본시험/재시험과 표본 수·집계 기간을 명시한다.
- 리포트는 발견→개입→확인된 변화→다음 계획을 근거 기록과 연결한다. 내부·검토 중 기록은 공유하지 않는다.
- 검토·승인·수정 상태와 공유용 화면을 확인한다. 실제 AI는 연결하지 않는다.

검증: 학생 3명의 기록과 리포트 문구 대조, 기간 경계, 기록 없음, 필터 후 분모, 내부 기록 제외, 수정 시 재검토, 승인본 보존.

## 6단계 — 실제 운영 전환 (이번 범위 밖의 별도 프로젝트)

사용자 체험 피드백 후 로그인·서버 권한, 데이터 모델과 마이그레이션, 기기 간 공유, 동시 편집 충돌, 백업·복원과 감사 이력을 설계한다. 교사/원어민/조교 접근범위와 학생 개인정보 처리 기준을 확인한다. 실제 데이터 도입 전 권한별 테스트, 백업 복원 연습, 제한된 파일럿을 통과한다. 실제 AI·문자 발송은 별도 승인 범위로 유지한다.

## 셀프 리뷰 및 적용 범위

- 사람: 3·4단계 / 흐름: 2·4단계 / 데이터: 1·3·4단계 / 권한: 2·6단계 / 출력: 5단계 / 복구: 0·1·4·6단계.
- 본 문서는 전체 순서와 첫 구현 단계의 상세 계획이다. 3~6단계는 각각 별도 실행 계획으로 확정하며, 아직 구현 승인 또는 완료를 뜻하지 않는다.
- 원래 PRD의 모든 고도화 기능을 이번 개선에 포함하지 않는다. 음성입력, 학부모 포털, 고급 분석, 실제 AI/발송은 후속 범위다.
- 일정이나 크레딧 비용은 측정되지 않았으므로 확정치로 제시하지 않는다.
