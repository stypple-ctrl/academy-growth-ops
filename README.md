# 이음 · 학생 성장관리와 학원 업무협업

교사·조교·원장이 한 학생의 기록을 이어서 사용하고, 그 기록을 다음 수업과 학부모 상담에 활용하도록 만드는 프로그램입니다.

**현재는 개발 중인 체험판입니다.** 가상 데이터로 업무 흐름을 확인하고 피드백을 받은 뒤, 실제 운영을 위한 DB와 인증을 연결할 예정입니다.

> **진행 상태 · 2026-10-08 기준**
>
> 기본 체험판과 1단계 개선 구현, 코드 검증까지 완료했습니다. 실제 화면·클릭 검증과 사용자 인수는 확인 대기입니다. 2단계 운영 기준은 2026-10-08 사용자 지시에 따라 확정·사례 검토를 마쳤습니다. 3단계 명단 입력과 선택 복습의 완료·집계·알림 연결까지 구현하고 코드 검사를 통과했습니다. 전체 단계 완료는 아닙니다.

## 교사 입력 개선 · 2026-10-08

교사 → 수업 기록에서 학생별 정답수를 입력하고 **입력한 점수 저장**을 누릅니다. 빈칸은 미입력, 0은 0점이며 FAIL 학생만 나머지 지정으로 이어집니다. 이 명단형 시험의 중복 과제 지정을 차단합니다. 관찰 입력에는 빠른 태그를, 수업 화면에는 ‘특이사항 없음 · 수업 마감’을 추가했습니다.

입력한 점수는 화면 이동 시 유지되지만 **새로고침하면 미저장 점수는 사라집니다.** 새로 지정하는 추가 과제는 **선택 복습**이 기본이며 교사가 필수로 변경할 수 있습니다. 선택 복습이 남아도 필수 과제가 끝나면 완료로 집계됩니다. 기존 과제의 필수 기준은 유지됩니다. [구현 결과·체험 경로·남은 제한](docs/reports/2026-10-08-phase-3-input-result.md)

## 현재 디자인 · 밝은 컬러 대시보드

2026-10-08 사용자가 선택한 Dashboard UI Kit 스크린샷 두 장을 기준으로 실제 테마를 적용했습니다. 흰색·연회색 바탕, 단순한 메뉴, 선명한 색상 카드, 얇은 구분선으로 정리했습니다. 원장 상황판은 확인 전/진행 중/신입 적응/후속 확인 완료를 구분하고, 학습실은 상태별 색상과 텍스트를 함께 표시합니다.

현재 `index.html`은 `clean-dashboard.css`를 로드합니다. 이전 macOS 테마 파일은 보관하며 활성 테마로 로드하지 않습니다. 기존 교사 입력 개선은 새 테마에 유지했습니다. 키트의 이미지·폰트를 복사하지 않고 참고 이미지의 방향에 맞춰 직접 구현했습니다.

기능 회귀·구문 검사와 주요 신규 색상쌍의 대비 계산을 통과했습니다. 실제 브라우저 배치·터치 검증은 접근 제한으로 미완료이며 완료 커밋은 보류했습니다. [적용 결과](docs/reports/2026-10-08-clean-dashboard-design.md)

## 나머지 학습실 · 학생 카드 갤러리

첨부 갤러리 예시의 격자 배치·상세 펼치기 방식을 참고했습니다. 상태별 가로 섹션 안에 넓은 학생 카드를 배치하고, 학생별 고정 색상 헤더·큰 이름·이름 표식·명시적 상태·카드 경계와 그림자를 적용했습니다. 카드의 ‘지시서 크게 보기’로 기존 작업 지시서를 엽니다. 학생 표식은 사진을 대신하는 이름이며 색상은 6종을 순환 사용합니다.

현재 순수 JavaScript 구조에 맞춰 구현했으며 첨부 문서의 React/TypeScript 전환·외부 사진 설치 지시는 실행하지 않았습니다. 전용 스타일은 `student-gallery.css`입니다. 지시서 확대는 기존 대화상자를 사용하며 이미지 공유요소 애니메이션·드래그 닫기는 포함하지 않습니다.

카드 누락·상태 이동 후 색상 유지·지시서 열기·기존 저장 복구 검사 통과. 실제 브라우저 화면 검증은 접근 제한으로 미완료이며 완료 커밋은 보류했습니다.

## 이전 시안 · 따뜻하고 귀여운 원장 화면

이전 시안은 크림색 배경, 노란색 버튼, 둥근 카드, 자체 제작한 새싹 캐릭터로 바꾼 디자인 시안입니다. 카카오 로그인 가이드는 로그인 버튼 전용 자료이므로, 카카오 로고·캐릭터 대신 자체 그래픽으로 친근한 분위기를 표현했습니다. 원장 상황판과 그 화면에서 여는 대화상자에 적용되며 교사·조교 화면은 기존 디자인을 유지합니다.

전용 스타일은 `director-theme.css`에 분리했습니다. 역할별 동작·저장 복구·템플릿 검사 통과. 실제 브라우저 시각 검증은 기존 접근 제한으로 미완료이며, 프로젝트 지침에 따라 완료 커밋은 보류했습니다.

## Apple HIG 참고 디자인 · 2026-10-07

[Apple Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines/)의 정보 위계·정렬·색상·접근성 원칙을 웹 화면에 맞춰 적용했습니다. 회색·흰색 표면, 파란색 주요 동작, 통일된 선형 아이콘, 읽기 쉬운 글자와 터치 영역을 반영했습니다. Apple 네이티브 UI나 Liquid Glass의 완전한 구현을 의미하지 않습니다.

역할별 업무 흐름과 저장 기능 검사 통과. 주요 텍스트·버튼·상태 색상쌍 대비 검사 통과. 실제 브라우저 배치·터치·접근성 전체 검증은 미완료이며 완료 커밋은 보류했습니다. [적용 내역](docs/reports/2026-10-07-hig-design.md)

## 역할별 UI·UX 체험 · 2026-10-07

원장·교사·조교의 실제 사용 목적에 맞춰 첫 화면을 개편했습니다. 우측 상단 역할 선택으로 전환합니다.

- **원장:** 신입생 적응 여정, 재원 관심 알림, 가상 등록·퇴원 내역, 교사별 후속 관리. 학생의 ‘확인하기’에서 확인 중·완료를 저장해보세요.
- **교사:** 챙길 학생, 빠른 수업 기록, 학생 선택 후 상담 초안과 근거 보기. 원장에서 바꾼 확인 상태가 함께 표시됩니다.
- **조교:** 지난 근무 이후 브리핑, 인계 확인, 학생별 ‘오늘 할 일 · 지시서’, 객관식 5문항 채점 체험.

신입 적응·재원 관심·등록/퇴원·근무 일정은 **가상 시나리오**입니다. 상담은 공유 가능 기록의 분류이며 AI 분석은 연결 전입니다. 5문항 채점 예시는 학생 기록·재시험 점수에 저장하지 않습니다. 확인 상태와 인계 확인은 현재 브라우저에 저장됩니다.

기존 학습 상세 현황은 원장 상황판 하단에서 펼칠 수 있습니다. 기존 저장 데이터는 초기화하지 않습니다. 실제 화면·클릭 검증은 브라우저 접근 제한으로 대기 중이며 완료 커밋·GitHub push는 보류했습니다. [역할별 체험 결과와 제한](docs/reports/2026-10-07-role-experience.md)을 참고하세요.

## 우리가 만들려는 것

학습 문제를 기록하는 데서 끝내지 않고, **발견 → 지도·개입 → 수행 결과 → 변화 확인 → 다음 계획**까지 이어지는 학생 관리 도구를 목표로 합니다.

| 사용자 | 목표 |
|---|---|
| 교사 | 수업 직후 필요한 학생만 빠르게 기록하고, 지난 결과를 다음 수업에 활용 |
| 조교 | 나머지 과제와 완료 조건을 확인하고 수행 사실·남은 과제를 간단히 전달 |
| 원장 | 확인이 필요한 학생과 업무를 찾아 담당자·다음 조치를 파악 |
| 학부모 | 월말리포트를 통해 학원이 무엇을 발견하고 도왔으며 무엇이 달라졌는지 이해 |

실사용 목표는 교사의 수업 후 기록 평균 1~2분, 조교의 학생별 완료 처리 15초 이내입니다. **아직 실제 사용 시간으로 검증하지 않은 목표치입니다.**

## 어디까지 진행했나

아래 단계는 **현재 개선 작업의 순서**입니다. 원본 PRD의 MVP 번호와는 별개입니다.

| 단계 | 범위 | 상태 | 다음으로 넘어가기 위한 기준 |
|---|---|---|---|
| 초기 체험판 | 역할별 화면과 기록·나머지·리포트 연결 | 구현됨 · 실제 UI 검증 미완료 | 주요 업무 흐름 체험 확인 |
| 0. 기존 버전 보존 | 변경 전 소스 복구본 보존 | 완료 · 로컬에 보관 | 필요한 소스 복구 경로 확보 |
| 1. 작은 신뢰성 오류 수정 | 기본값·집계·용어·설명·저장 실패 처리 | **구현 및 코드 검증 완료 / UI·인수 대기** | 계약의 필수 확인 완료 |
| 2. 운영 기준 결정 | 추가 과제·이월 책임·정정·승인본 기준 | **운영 기준 확정 · 사례 검토 완료** | 사용자 기준 확정, 가상 사례 대조 |
| 3. 교사 입력 개선 | 명단형 점수 입력·빠른 태그·수업 마감 | **1차 구현·코드 검사 통과 / UI·통합 잔여** | 짧은 동선에서 정확하게 기록 |
| 4. 조교와 인계 개선 | 부분완료·귀가·결과 확인·정정 | 선택 복습 완료·집계·알림 연결만 선행 구현 / 인계·정정 잔여 | 남은 과제와 담당자 명확화 |
| 5. 원장과 학부모 출력 | 우선조치 목록·의미 있는 지표·근거 기반 리포트 | 예정 | 기록을 실제 판단과 설명에 활용 |
| 6. 실제 운영 준비 | DB·로그인·권한·백업·동시 수정 | 별도 후속 프로젝트 | 개인정보 투입 전 검증과 제한된 파일럿 |

### 1단계에서 바뀐 점

- 조교의 도움 정도·진행 상태는 **미확인**으로 시작하며, 선택한 사실만 기록합니다.
- 나머지 대상은 **고유 학생 인원**으로 계산합니다. 과제 건수와 완료율은 과제 기준입니다.
- 화면 용어를 **기본 과제·추가 과제·미해결**로 정리했습니다.
- **현재 상태**와 **선택 기간의 기록**을 구분하고, 버튼명을 실제 이동 목적에 맞췄습니다.
- 저장 실패 시 성공으로 안내하지 않고 입력을 유지하며, 미저장 변경을 복구합니다. 재시도 시 사건 중복을 방지합니다.
- 기존 저장 키와 데이터 버전을 유지합니다. 업데이트 확인을 위해 데모 데이터를 초기화할 필요가 없습니다.

### 아직 남은 확인

실제 브라우저 접근 권한 차단으로 화면 배치·클릭 동작은 직접 검증하지 못했습니다. 코드 검사 통과를 실제 UI 검증 완료로 간주하지 않습니다. 계약상 1단계의 최종 인수도 아직 대기 상태입니다.

## 확정된 운영 기준과 남은 구현

[2단계 작업계약 확정본](docs/work-agreements/2026-10-08-phase-2.md)에 확정 기준과 다섯 가상 사례를 정리했습니다. 선택 복습·필수 기준 완료는 앱에 반영했고, 잔여 기록·확인일·정정·승인본 보존은 후속 구현입니다.

2단계는 코드를 대규모로 고치는 단계가 아니라 **학원의 운영 기준을 확정하는 단계**입니다. 기본 선택 복습·필수 과제 기준 완료·조교 잔여 기록/교사 확인일·정정 이력 보존·승인본 보존으로 확정했습니다.

1. 추가 과제를 기본적으로 필수로 할지, 선택 복습으로 할지.
2. 기본 과제만 완료하고 추가 과제가 남았을 때 어떤 상태로 표시할지.
3. 미완료 범위 기록과 다음 확인일 지정은 누가 맡을지.
4. 잘못된 기록을 정정할 때 원본·사유·이력을 어떻게 남길지.
5. 승인된 리포트의 근거 기록이 바뀌었을 때 승인본과 수정본을 어떻게 관리할지.

[3단계 교사 입력 계획](docs/superpowers/plans/2026-10-08-phase-3-teacher-input.md)의 시험 연결과 관찰 미저장 보호를 구현했고 실제 화면 확인·인수가 남았습니다. 이후 조교의 잔여 범위·교사 확인일, 정정 이력, 원장·리포트 순으로 개선합니다.

## 실행 방법

Python 3가 있는 환경에서 저장소를 내려받아 실행합니다. 웹 앱 실행에 npm 패키지 설치나 DB 설정은 필요하지 않습니다.

```bash
git clone https://github.com/stypple-ctrl/academy-growth-ops.git
cd academy-growth-ops
python3 -m http.server 4173 --bind 127.0.0.1
```

브라우저에서 [로컬 체험판](http://127.0.0.1:4173)을 엽니다. 이 주소는 위 서버를 실행한 컴퓨터에서 사용하는 주소이며, 온라인 배포 주소가 아닙니다. 종료는 터미널에서 `Ctrl+C`를 누릅니다.

### 권장 체험 순서

1. 상단 역할을 **교사**로 변경하고 수업 기록에서 김민수를 선택합니다.
2. 단어시험 정답수 **21개**를 입력하고, FAIL 후 제안되는 나머지 과제를 지정합니다.
3. **조교**로 전환해 새로 지정한 대기 카드를 찾아 입실·시작 처리합니다. 같은 학생의 초기 카드가 있으므로 과제와 상태를 확인합니다.
4. 정답수 **24개**로 재시험 결과를 저장하고, 제시되는 추가 과제를 완료하거나 미완료 귀가 처리합니다.
5. **원장 또는 교사**로 전환해 학생 360과 학부모 알림 검토에서 결과를 확인합니다.
6. 월말리포트에서 **2026-09** 샘플 또는 **2026-10** 입력 기록을 선택하고 수정 → 승인 → 인쇄/PDF 저장을 체험합니다.

변경 내용은 현재 브라우저의 localStorage에 저장됩니다. 같은 브라우저·같은 주소로 접속해야 기존 체험 데이터를 이어서 사용할 수 있습니다. 설정의 초기화 버튼은 추가 기록과 수정 리포트를 지우므로, 처음 상태로 돌아가고 싶을 때만 사용합니다.

Node.js가 있는 환경에서 저장소 루트에서 실행합니다.

```bash
node --check app.js

```

최근 재검증에서 위 검사는 모두 통과했습니다. 검사 범위는 다음과 같습니다.

- 23개 FAIL / 24개 PASS, 추가 과제 전환, 미완료 이월, 리포트 공개 범위.
- 새 선택 복습·필수 지정, 기존 과제 기준 보존, 선택 잔여의 완료 집계, 저장 실패 복구.
- 완료 후 미발송 안내 취소·모의 발송 시각 보존, 필수 잔여 변경 시 재검토·이전 안내 이력 보존.
- 미확인·부분 선택·명시적 관찰, 인원 중복 제거, 과제 분모, 빈 조회 결과.
- 9개 화면 템플릿, 역할별 메뉴, 필터와 표시 용어.
- 학생별 바로가기 대상·조회 범위, 빈 선택 버튼 차단, 과제 카드 누락·중복 방지, 확인대기 우선 배치와 완료 접기.
- 저장 실패 복구, 입력·선택 유지, 재시도 중복 방지, 재조회 및 기존 데이터 보존.

화면 검사는 DOM 대체 환경을 사용합니다. 실제 브라우저 배치·클릭·성능·사용성 검사를 대신하지 않습니다. `npm test`는 현재 모델 검사만 실행하므로 전체 확인에는 위 명령을 사용합니다.

## 체험판의 제한

- 실제 학생 데이터를 입력하는 운영 환경이 아닙니다. 로그인·서버 권한·DB·다른 기기 간 공유는 없습니다.
- 같은 브라우저의 동일 출처 탭 간 변경 반영은 있지만, 동시 편집 충돌 해결은 없습니다.
- 소스 코드의 Git 기록과 로컬 복구본은 브라우저 데이터 백업이 아닙니다. 데이터 백업·복원 기능은 아직 없습니다.
- 데모 기준일은 **2026-10-01**로 고정되어 있습니다. 오늘 날짜 기반 운영 스케줄이 아닙니다.
- 재시험·패턴 탐지는 단순 체험용 로직입니다. 실제 운영 정책 확정과 추가 검증이 필요합니다.
- 추가 과제의 필수 여부, 부분완료, 업무 취소·정정 이력은 아직 개선 전입니다.
- 학생·반·사용자 관리 기능 확대, 음성메모, 학생별 자동 셔틀 스케줄은 후속 범위입니다. 경과시간 경고는 화면 갱신 시 계산합니다.
- 리포트는 AI 없이 템플릿으로 생성하며, 알림 발송은 시뮬레이션입니다. PDF는 브라우저 인쇄의 PDF 저장을 사용합니다.
- Vercel 테스트 배포가 완료되었습니다: https://academy-growth-ops.vercel.app/

### 교사 프론트엔드 1차 개선 · 2026-10-08

수업 기록 화면에 입력 순서, 학생별 PASS/FAIL 예상·미저장·오류·오늘 저장된 시험 표시, 미저장 인원수를 추가했습니다. 점수 칸에서 Enter는 다음 학생, Shift+Enter는 이전 학생으로 이동합니다. 관찰 작성 중 닫기·Escape·메뉴·역할 전환에는 폐기 확인이 있으며, 저장 실패 시 내용을 유지합니다. 미저장 관찰은 수업 마감을 막습니다. 새로고침 경고를 요청하지만 초안을 영구 저장하지는 않습니다.

현재 macOS 테마를 유지하며 입력 표·저장 영역·모바일 버튼 배치를 개선했습니다. 코드 검사는 통과했고 실제 화면 배치·브라우저 경고·키보드 체감은 미검증입니다. [상세 결과](docs/reports/2026-10-08-teacher-input-ux.md)


### Vercel 테스트 배포 · 2026-10-08

현재 체험판을 배포 테스트용 중간 저장으로 기록했습니다. 최신 화면은 `clean-dashboard.css`의 밝은 배경과 색상 구분을 사용합니다. 기존 디자인 문서의 테마 설명은 당시 기록입니다.

1. [Vercel 새 프로젝트](https://vercel.com/new)에서 로그인합니다.
2. GitHub의 `stypple-ctrl/academy-growth-ops` 저장소를 Import 합니다. 연결 권한 선택 시 이 저장소만 선택합니다.
3. Production Branch는 `main`, Framework Preset은 **Other**, Root Directory는 기본값을 사용합니다.
4. Build Command는 `npm run build`, Output Directory는 `dist`입니다. `vercel.json`에 설정되어 있습니다. 환경변수는 필요 없습니다.
5. Deploy를 누르고 완료되면 생성된 주소로 접속합니다.

빌드는 외부 패키지 없이 실행에 필요한 6개 파일만 `dist/`에 복사합니다. 문서·테스트·로컬 복구본은 배포 결과물에 포함하지 않습니다. 검색 제외 헤더는 접근 제한이나 로그인 기능이 아닙니다.

검증: `npm run build`, `npm run test:all`, `git diff --check` 통과. 실제 배포 주소의 화면·클릭·저장 검증은 아직 남아 있습니다. 배포 후 원장·교사·조교 전환, 학생 카드 열기, 점수 저장 후 새로고침을 확인해야 합니다.

배포 주소에서는 가상 데이터로 새로 시작합니다. 기존 localhost의 브라우저 데이터는 옮겨지지 않으며, 다른 기기와 공유되지 않습니다. 실제 학생 개인정보를 입력하지 마세요. DB·로그인·서버 권한은 후속 작업입니다.
