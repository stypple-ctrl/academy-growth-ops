# 이음 · 학생 성장관리와 학원 업무협업

교사·조교·원장이 한 학생의 기록을 이어서 사용하고, 그 기록을 다음 수업과 학부모 상담에 활용하도록 만드는 프로그램입니다.

**현재는 개발 중인 체험판입니다.** 가상 데이터로 업무 흐름을 확인하고 피드백을 받은 뒤, 실제 운영을 위한 DB와 인증을 연결할 예정입니다.

> **진행 상태 · 2026-10-07 기준**
>
> 기본 체험판과 1단계 개선 구현, 코드 검증까지 완료했습니다. 실제 화면·클릭 검증과 사용자 인수는 확인 대기입니다. 2단계 운영 기준 결정은 미착수이며, 2단계 작업계약서는 아직 작성하지 않았습니다.

## 우리가 만들려는 것

학습 문제를 기록하는 데서 끝내지 않고, **발견 → 지도·개입 → 수행 결과 → 변화 확인 → 다음 계획**까지 이어지는 학생 관리 도구를 목표로 합니다.

| 사용자 | 목표 |
|---|---|
| 교사 | 수업 직후 필요한 학생만 빠르게 기록하고, 지난 결과를 다음 수업에 활용 |
| 조교 | 나머지 과제와 완료 조건을 확인하고 수행 사실·남은 과제를 간단히 전달 |
| 원장 | 확인이 필요한 학생과 업무를 찾아 담당자·다음 조치를 파악 |
| 학부모 | 월말리포트를 통해 학원이 무엇을 발견하고 도왔으며 무엇이 달라졌는지 이해 |

실사용 목표는 교사의 수업 후 기록 평균 1~2분, 조교의 학생별 완료 처리 15초 이내입니다. **아직 실제 사용 시간으로 검증하지 않은 목표치입니다.**

## 현재 체험할 수 있는 것

| 기능 | 현재 구현 수준 |
|---|---|
| 역할 선택 | 원장·교사·조교 화면 전환. 실제 로그인·보안 권한은 아님 |
| 교사 수업 기록 | 학생 다중선택, 관찰 입력, 단어시험 결과, 나머지 지정 |
| 단어시험 | 기본 30문항, 24개 이상 PASS. 문항수·기준 변경 가능 |
| 나머지 운영보드 | 대기·학습중·확인대기·완료·미완료 처리, 기본 과제 후 추가 과제 제시 |
| 학생 360 | 담임·원어민·조교·시험·과제 기록의 통합 타임라인 |

| 원장 대시보드 | 교사·반·학교·학년별 조회, 기록 기간·유형 필터, 인원·과제·Case 집계와 그래프 |
| 학부모 알림 | 미완료 안내 검토·승인·발송 시뮬레이션. 실제 발송 없음 |
| 월말리포트 | 공유 가능한 월별 기록으로 템플릿 초안 작성, 수정·승인·브라우저 인쇄 |

가상 학생 48명, 6개 반, 담임교사 3명과 원어민교사 1명, 초기 나머지 카드 10개를 제공합니다. 디자인은 부드러운 입체형 컨트롤과 민트·연두색을 사용합니다.

## 어디까지 진행했나

아래 단계는 **현재 개선 작업의 순서**입니다. 원본 PRD의 MVP 번호와는 별개입니다.

| 단계 | 범위 | 상태 | 다음으로 넘어가기 위한 기준 |
|---|---|---|---|
| 초기 체험판 | 역할별 화면과 기록·나머지·리포트 연결 | 구현됨 · 실제 UI 검증 미완료 | 주요 업무 흐름 체험 확인 |
| 0. 기존 버전 보존 | 변경 전 소스 복구본 보존 | 완료 · 로컬에 보관 | 필요한 소스 복구 경로 확보 |
| 1. 작은 신뢰성 오류 수정 | 기본값·집계·용어·설명·저장 실패 처리 | **구현 및 코드 검증 완료 / UI·인수 대기** | 계약의 필수 확인 완료 |
| 2. 운영 기준 결정 | 추가 과제·이월 책임·정정·승인본 기준 | **미착수** | 사용자 기준 확정, 가상 사례 대조 |
| 3. 교사 입력 개선 | 명단형 점수 입력·빠른 태그·수업 마감 | 예정 | 짧은 동선에서 정확하게 기록 |
| 4. 조교와 인계 개선 | 부분완료·귀가·결과 확인·정정 | 예정 | 남은 과제와 담당자 명확화 |
| 5. 원장과 학부모 출력 | 우선조치 목록·의미 있는 지표·근거 기반 리포트 | 예정 | 기록을 실제 판단과 설명에 활용 |
| 6. 실제 운영 준비 | DB·로그인·권한·백업·동시 수정 | 별도 후속 프로젝트 | 개인정보 투입 전 검증과 제한된 파일럿 |

### 1단계에서 바뀐 점

- 조교의 도움 정도·진행 상태는 **미확인**으로 시작하며, 선택한 사실만 기록합니다.
- 나머지 대상은 **고유 학생 인원**으로 계산합니다. 과제 건수와 완료율은 과제 기준입니다.
- 화면 용어를 **기본 과제·추가 과제·미해결**로 정리했습니다.
- **현재 상태**와 **선택 기간의 기록**을 구분하고, 버튼명을 실제 이동 목적에 맞췄습니다.
- 저장 실패 시 성공으로 안내하지 않고 입력을 유지하며, 미저장 변경을 복구합니다. 재시도 시 사건 중복을 방지합니다.
- 기존 저장 키와 데이터 버전을 유지합니다. 업데이트 확인을 위해 데모 데이터를 초기화할 필요가 없습니다.

### 아직 남은 확인

실제 브라우저 접근 권한 차단으로 화면 배치·클릭 동작은 직접 검증하지 못했습니다. 코드 검사 통과를 실제 UI 검증 완료로 간주하지 않습니다. 계약상 1단계의 최종 인수도 아직 대기 상태입니다.

## 다음에 결정할 내용

2단계는 코드를 대규모로 고치는 단계가 아니라 **학원의 운영 기준을 확정하는 단계**입니다. 아래 내용은 아직 결정된 정책이 아닙니다.

1. 추가 과제를 기본적으로 필수로 할지, 선택 복습으로 할지.
2. 기본 과제만 완료하고 추가 과제가 남았을 때 어떤 상태로 표시할지.
3. 미완료 범위 기록과 다음 확인일 지정은 누가 맡을지.
4. 잘못된 기록을 정정할 때 원본·사유·이력을 어떻게 남길지.
5. 승인된 리포트의 근거 기록이 바뀌었을 때 승인본과 수정본을 어떻게 관리할지.

1단계의 남은 확인을 처리하고, 위 기준을 합의해 2단계 작업계약을 구체화하는 것이 다음 순서입니다. 이후 교사 입력 → 조교 처리 → 원장·리포트 순으로 개선합니다.

## 실행 방법

Python 3가 있는 환경에서 저장소를 내려받아 실행합니다. 웹 앱 실행에 npm 패키지 설치나 DB 설정은 필요하지 않습니다.

```bash
git clone https://github.com/stypple-ctrl/academy-growth-ops.git
cd academy-growth-ops
python3 -m http.server 4173 --bind 127.0.0.1
```

브라우저에서 [로컬 체험판](http://127.0.0.1:4173)을 엽니다. 이 주소는 위 서버를 실행한 컴퓨터에서 사용하는 주소이며, 온라인 배포 주소가 아닙니다. 종료는 터미널에서 `Ctrl+C`를 누릅니다.

### 권장 체험 순서

1. 상단 역할을 **교사**로 변경하고 수업 기록에서 김민수를 선택합니다.
2. 단어시험 정답수 **21개**를 입력하고, FAIL 후 제안되는 나머지 과제를 지정합니다.
3. **조교**로 전환해 새로 지정한 대기 카드를 찾아 입실·시작 처리합니다. 같은 학생의 초기 카드가 있으므로 과제와 상태를 확인합니다.
4. 정답수 **24개**로 재시험 결과를 저장하고, 제시되는 추가 과제를 완료하거나 미완료 귀가 처리합니다.
5. **원장 또는 교사**로 전환해 학생 360과 학부모 알림 검토에서 결과를 확인합니다.
6. 월말리포트에서 **2026-09** 샘플 또는 **2026-10** 입력 기록을 선택하고 수정 → 승인 → 인쇄/PDF 저장을 체험합니다.

변경 내용은 현재 브라우저의 localStorage에 저장됩니다. 같은 브라우저·같은 주소로 접속해야 기존 체험 데이터를 이어서 사용할 수 있습니다. 설정의 초기화 버튼은 추가 기록과 수정 리포트를 지우므로, 처음 상태로 돌아가고 싶을 때만 사용합니다.

## 검증 방법과 범위

Node.js가 있는 환경에서 저장소 루트에서 실행합니다.

```bash
node --check app.js
node --check model.js
node test-model.cjs
node test-render.cjs
node test-storage.cjs
```

최근 재검증에서 위 검사는 모두 통과했습니다. 검사 범위는 다음과 같습니다.

- 23개 FAIL / 24개 PASS, 추가 과제 전환, 미완료 이월, 리포트 공개 범위.
- 미확인·부분 선택·명시적 관찰, 인원 중복 제거, 과제 분모, 빈 조회 결과.
- 9개 화면 템플릿, 역할별 메뉴, 필터와 표시 용어.
- 저장 실패 복구, 입력·선택 유지, 재시도 중복 방지, 재조회 및 기존 데이터 보존.

화면 검사는 DOM 대체 환경을 사용합니다. 실제 브라우저 배치·클릭·성능·사용성 검사를 대신하지 않습니다. `npm test`는 현재 모델 검사만 실행하므로 전체 확인에는 위 명령을 사용합니다.

## 체험판의 제한

- 실제 학생 데이터를 입력하는 운영 환경이 아닙니다. 로그인·서버 권한·DB·다른 기기 간 공유는 없습니다.
- 같은 브라우저의 동일 출처 탭 간 변경 반영은 있지만, 동시 편집 충돌 해결은 없습니다.
- 소스 코드의 Git 기록과 로컬 복구본은 브라우저 데이터 백업이 아닙니다. 데이터 백업·복원 기능은 아직 없습니다.
- 데모 기준일은 **2026-10-01**로 고정되어 있습니다. 오늘 날짜 기반 운영 스케줄이 아닙니다.
- 재시험·패턴 탐지는 단순 체험용 로직입니다. 실제 운영 정책 확정과 추가 검증이 필요합니다.
- 추가 과제의 필수 여부, 부분완료, 업무 취소·정정 이력은 아직 개선 전입니다.
- 학생·반·사용자 관리 기능 확대, 음성메모, 학생별 자동 셔틀 스케줄은 후속 범위입니다. 경과시간 경고는 화면 갱신 시 계산합니다.
- 리포트는 AI 없이 템플릿으로 생성하며, 알림 발송은 시뮬레이션입니다. PDF는 브라우저 인쇄의 PDF 저장을 사용합니다.
- 저장소 공개와 앱 온라인 배포는 다릅니다. 이 저장소에는 온라인 배포를 설정하지 않았습니다.
